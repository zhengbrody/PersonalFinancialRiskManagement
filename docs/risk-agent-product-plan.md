## 1. 定位与目标用户

定位：帮助自主投资者在改变持仓之前，验证一个决定对整个账户风险的影响，并在之后检查原来的假设是否仍成立。

不是另一个选股聊天窗口。用户交付的任务是“检查—模拟—比较—保存—复查”，Agent 交付的是可继续操作的分析，而非一份孤立报告。

第一目标人群：持有美股/ETF，兼有期权组合或融资的自主投资者。以组合风险理解为核心，不同时扩张成退休规划、所有资产研究或自动交易系统。

候选产品承诺：**Before you change your portfolio, understand what could change your risk.**

## 2. 竞品事实与差异化假设

| 产品 | 官方已公开的能力 | 对 MindMarket 的启示 |
| --- | --- | --- |
| Robinhood Cortex | 结合账户数据处理持仓问题、研究与应用内操作 | 实时账户上下文和工具调用已是基本能力，不能作为独有卖点 |
| PortfolioPilot | 持仓分析、市场/退休模拟、筛选、草稿组合，结果卡可继续操作 | “会模拟、会生成草稿、不碰真实持仓”也不能单独形成差异 |
| OptionStrat | 期权策略盈亏可视化，调整价格、时间、波动率等因素 | 期权分析必须直观且策略级正确；不必重建一个完整的期权交易终端 |
| Composer | 自然语言构建策略、回测及执行 | MindMarket 选择决策验证而非自动执行，明确自己的产品边界 |

以上不能证明竞品没有某个功能。我们的差异化是待验证的组合优势：

1. **先验证输入，再评判风险**：成本与当前估值、期权腿方向、净权益与本金、现金与购买力出现冲突时，提出可解决的问题，局部阻断受影响分析。
2. **策略风险与账户风险一起看**：到期损失上限、到期前模型压力、股票集中度、融资余额和流动性缓冲并排展示，不把一个数字当成完整风险。
3. **同一基线上的决策对比**：保留“不改变”的方案；所有候选方案使用相同持仓快照、价格时点、情景和模型版本，展示代价而非只追求分数提升。
4. **假设有后续**：用户保存的是决策依据与复查条件；之后只解释哪些依据变了，不重复发送泛泛的市场报告。

可积累的优势来自真实问题回归集、数据一致性规则、可重放的计算结果和用户确认的决策历史，而不是 Agent 数量。

## 4. 第一版真实任务

### A. Check my portfolio（首发主任务）

用户点击后：确认当前组合 → 自动检查数据 → 检查策略/集中度/融资 → 只呈现最重要的 1–3 项 → 提供“看依据”“补数据”“测试影响”。

Agent 根据工具结果选择下一步。例如发现价差组合则按组计算，不再逐腿提示无限损失；发现成本缺失则区分“无法确认建仓最大损失”与“可按当前估值做情景分析”，不要求用户补完所有历史资料才可继续。

### B. Test a change（第二阶段）

用户指定一个假设变更或选择风险项后，Agent：

- 收集必要约束：保留哪些持仓、预留现金、是否允许新增融资、测试期限；只追问缺失且会改变结果的内容。
- 生成至多两个可行替代方案，加上“不改变”基线；允许用户修改假设后重跑。
- 展示净权益、情景损益、集中度、融资余额/现金缓冲、期权策略状态、数据置信度及不能计算的内容。
- 方案优劣基于用户确认的约束及多维结果，不能只按 Health Score 排序；无合适方案时明确说没有。
- 只有点击 Confirm save 才保存为风险计划，不写真实持仓、不下单。

### C. Does this idea fit my portfolio?（第三阶段）

用户直接在 Copilot 提出研究想法，或从 Research 的“Test in my portfolio”携带标的上下文进入同一 Copilot 窗口。后续追问、测试和比较均在对话内完成。Agent 先检查与当前持仓的重复行业/标的风险，再按用户输入的假设金额测试，而不是只回答公司好坏。

新闻和用户观点是待检验的假设，不因被写进聊天就变成证据。外部文本不可改变工具权限、组合身份或风控规则。

### D. Review my plan（第四阶段）

先提供手动复查。之后经用户明确开启，才增加站内周期/条件触发复查：风险阈值、组合变化、期权临近到期或关键数据失效。

返回“哪条原假设失效、哪些指标变了、是否值得重跑”，而非“Agent 为你赚了多少”。没有用户确认的实际持仓变化，不计算虚构的执行收益。

## 5. Copilot 单窗口交互

Copilot 就是 Agent 的操作界面，而不只是通往其他页面的聊天入口。不增加主导航入口，不要求用户在 Chat/Agent 模式之间选择，不为分析另开窗口、任务页或嵌套抽屉。Analyze 保留为手动分析工具，完成 Agent 任务不依赖跳转过去。

| 窗口区域 | 用户体验 | 约束 |
| --- | --- | --- |
| 顶部上下文 | 当前组合、数据时点、运行状态 | 切换组合加载隔离的对话上下文；旧任务始终绑定原组合，不重新贴标签 |
| 起始建议 | Check my portfolio / Test a change / Review a plan | 只是发起任务的快捷按钮，不是三个独立模式；也可直接输入问题 |
| 同一输入框 | 自然语言提问、补充约束、要求修改假设 | 普通问答不强制启动多步骤任务；需要确认的信息用对话内小表单收集 |
| 对话内进度卡 | 检查数据 → 计算风险 → 整理结果；支持停止、重试 | 展示真实阶段和工具状态，不展示内部思维链或虚构百分比 |
| 结果与证据卡 | 先显示最多 3 个重点；点击原地展开依据和数据缺口 | 事实、假设、模型结果分开标记；不默认铺开长报告 |
| 对话内比较卡 | 修改金额/约束后点击重算；对比不改变与最多两个候选 | 同一快照比较；移动端纵向卡片，不要求横向大表或新窗口 |
| 保存与复查卡 | 在对话内确认保存、查看保存状态、重新检验原假设 | 确认绑定精确方案版本；失败可重试且不重复保存 |

完整路径：在 Copilot 提问 → 原地补信息 → 原地看分析 → 原地调参数比较 → 原地确认保存 → 后续在 Copilot 复查。证据展开、错误恢复、停止和继续都不要求离开当前窗口。

Today/Research 只提供可选的上下文入口：进入 Copilot 时传递经过验证的组合/标的/计划标识，不自行另建任务或复制结果。现有浮动 Copilot 若保留，与完整 Copilot 共用同一对话及运行状态；切换展示方式不能产生第二套会话或重复执行。

复用现有 Copilot 会话容器和消息渲染体系，增加类型化的任务、表单、证据、比较和确认消息块；六段答案契约继续兼容，前端以摘要和按需展开呈现。组件按职责拆分，不将任务运行、金融计算与所有卡片塞进一个聊天组件。

手机仍在同一个 Copilot 会话中交互，输入框和卡片适应键盘及窄屏。新结果不得抢夺正在阅读或填表用户的焦点；历史消息阅读时显示“新结果”提示，按需滚动。失败、取消、部分完成、等待确认各有明确状态。

每张结论卡包含影响范围、数据时点、事实/假设/模型结果标签、证据入口和下一步。历史结果保留来源与过时标记；新假设产生新结果版本，不悄悄覆盖用户已审阅的内容。

## 6. 架构方案

一名有界协调 Agent + 多个类型化工具 + 独立确定性校验器。首版不建设多模型互相讨论的系统。

```text
Copilot 单窗口（Today / Research 仅提供可选上下文入口）
                  ↓
Run API：鉴权、组合绑定、输入与确认
                  ↓
Coordinator：解释任务，选择白名单工具，按结果有限调整步骤
                  ↓
Typed tool adapters → 现有评分 / 期权 / 融资 / 情景 / 研究服务
                  ↓
Deterministic validator → 可追溯结果 → 用户确认保存 → 复查
```

### 服务边界

- 协调器可以理解意图、提出追问、选择已有工具与解释结果；不能发明公式、执行任意 Python/SQL/shell、访问任意 URL、直接调用数据库修改工具。
- 从现有路由中逐步提取可复用服务，不复制风险引擎，不再把运行时塞进庞大的 `copilot_router.py`。旧聊天路由保持兼容。
- 新增模块按职责分为 run API/schema、协调器、工具适配、校验、运行存储；避免一个“万能 agent.py”。
- 每次运行绑定服务端确认的 user_id、conversation_id、run_id、portfolio_id、portfolio_revision、snapshot_id、engine_version、schema_version、assumptions 与时间戳。缓存与结果必须包含相应隔离及版本维度，不能只凭对话文字复用旧结果。
- 消息块引用服务端 run_id/result_version，聊天与 Agent 共用状态来源，不复制两份运行状态。所有金融卡片均由类型化工具结果驱动，不执行模型生成的任意 UI 代码或信任模型生成的表单权限。
- 工具输出包含 metric_id、单位、时间范围、基线、来源、计算版本、freshness、覆盖率和状态；匹配到相同数字并不等于支持相同结论。
- 跨工具要求数据时点相容；不相容时披露、重算或停止比较，不能拼接成“实时完整账户”。
- 保存确认绑定精确结果版本。服务器从该结果构造 RiskPlan，不信任浏览器回传的 expected_impact；旧计划保留来源标记，不追认为 Agent 验证结果。

### 运行与恢复

- 最小新增持久化模型为 runs 与 bounded step/results；优先复用现有 risk_plans、alerts、preferences，不另建第二套用户记忆系统。
- 状态：queued → validating → running → needs_input / ready_for_review → completed；另有 cancelled、failed、expired。partial coverage 是结果状态，不能伪装完整成功。
- 任务和状态事件持久化，幂等键防重复创建/保存；有界步骤、超时、重试、每用户并发限制、缓存与取消信号；刷新浏览器不丢任务。
- 对话内补充信息恢复原任务；改变计算假设生成新的结果版本并使旧确认失效。停止后不再调度后续工具，尚未结束的调用结果不得误显示为已完成任务。切换组合后原任务仍只属于原组合，并可回到其会话查看或取消。
- 首发单 worker 低并发，先验证小型生产实例的负载，重计算按需执行；不靠无限 BackgroundTasks 或内存队列保证持久性。
- worker 只能处理服务端鉴权后登记的指定租户/组合任务；不得存储长期用户 JWT，也不得把高权限数据库凭证交给模型。异步执行的最小权限/RLS 路径必须在阶段 1 审核清楚。
- 默认前台用户发起；后台持续复查放到阶段 4，单独设计授权、调度、过期与数据删除。

## 7. 金融与安全硬门槛

1. 同到期期权到期盈亏与到期前模型重估分开；展示建仓成本口径或当前估值口径；未知方向/合约乘数/标的身份不做确定性策略承诺。
2. “到期最大损失有界”不等于不存在提前指派、流动性或临时融资风险。跨到期不套用同到期精确上下界；首版将未支持部分明确列出。
3. 同标的同到期的净组合，不一定等于用户当初下单的独立策略。对复杂重叠腿展示净额分组依据，不虚构历史订单配对。
4. 现金类资产的市值偿债覆盖是估计，不是券商保证。模拟卖出偿债时资产与负债同步减少，不能重复加现金或凭空提高净权益；用户自分类资产不能获得无条件安全信用。
5. 只对模型覆盖部分给数值，不把未定价头寸计为零风险，不把“缺数据”写成“没有风险”。
6. 本金、净入金、投资损益、当前组合回测、实际 YTD 明确分开。只有数据足够且口径一致才做对应比较。
7. 低置信度可以输出数据整理和中性情景，不输出未经支持的方向性结论。用户假设必须保持假设标签。
8. 每个写操作有明确确认，且绑定内容与版本；越权、重复提交、切换组合、旧快照、注入攻击均须测试。跨用户内容不得进入日志/遥测；只记录必要枚举、耗时与错误类别。

## 8. 分阶段实施与验收

不按功能按钮机械拆 PR；按可独立验证/回滚的交付拆分。每阶段包含前后端、测试和一次完整用户流程，避免先建大量底层却无可用体验。

| 阶段 | 用户可见交付 | 工程工作 | 放行标准 |
| --- | --- | --- | --- |
| 1：可信风险体检 MVP | Copilot 内一键体检、真实进度、最多 3 个重点、原地补数据和展开证据 | 复用会话容器、类型化消息块、绑定快照、typed adapters、运行持久化、鉴权/隔离/取消、确定性校验 | 不离开 Copilot 完成一次闭环；缺价/成本缺失/方向冲突不误报；刷新与取消可验证；至少一个用户无需解释完成体检 |
| 2：决定前比较 | 同一对话内设置约束 → 保持不动 + 最多两个候选 → 修改重算 → 确认保存 | 交互比较卡、复用情景服务、同基线比较、服务端保存凭证、旧结果失效规则 | 资金守恒、期权净额、版本绑定、幂等保存全过；无覆盖数据不强行排名；能说清代价；全流程不跳页 |
| 3：Research 到组合 | 直接在 Copilot 研究并测试；Research 可携带标的进入同一窗口 | 上下文交接、研究数据门、组合相关性/集中度映射 | 两种入口使用同一计算来源；不把相关新闻当因果证明；研究到对比无需重输持仓或再次跳页 |
| 4：值得回来的复查 | Copilot 内复查已保存计划；授权后开启站内条件/周期复查，Today 可提示入口 | 复查消息卡、事件去重、阈值、防抖、授权调度、按持仓版本重算 | 无实质变化不重复打扰；一次事件一个稳定 episode；模型口径变化不标成持仓改善；可关闭并删除任务数据 |

### 第一版明确不做

- 自动交易、自动修改真实持仓、任意生成并执行策略代码。
- 不具备数据支持的所有期权策略“全覆盖”承诺。
- 新闻热点 Agent、通用股票推荐榜、多个拟人化 Agent 窗口。
- 无限后台扫描、未授权通知、仅为了延长停留时间的提醒。

## 9. 验收与产品指标

工程硬门：沿用现有 CI；增加工具合约、跨租户、重复请求、取消/恢复、旧确认拒绝、数值单位/时间范围、真实类型集成与浏览器 E2E。安全/金融边界失败必须阻止发布。

单窗口 E2E 硬门：从提问、补信息、证据展开到比较、保存和复查，不离开 Copilot；仅一个主输入框，不弹出第二聊天窗口；刷新恢复正确对话；重复点击不重复运行/保存；修改假设使旧确认失效；组合切换不串数据；桌面/移动端键盘操作、焦点、长消息滚动及错误恢复均验证。

专项回归至少覆盖：买卖方向双重取反；价差/蝶式/铁鹰极值；重复或缺失腿；跨到期；缺 IV/价格/成本；现金类偿债不重复计入；负净权益；中途切换组合；入金被误记收益；旧快照比较；与另一指标恰好相同的数字被误引用；外部文本工具注入。

产品指标是待测目标，不是当前成绩：

- 激活：发起体检的用户中，能完成结果查看并找到一项风险或确认无重点项的比例。
- 理解：小样本访谈中，用户能否讲清“主要风险、证据、下一步”，而不只是复述分数。
- 完成：发起比较后，完成约束设置、查看代价并确认保存/明确保持不动的比例。
- 持续价值：有已保存计划的用户中，7/28 天主动或有效触发复查的比例；不以推送点击当作收益。
- 质量：错误/中断率、需纠正结论比例、无价值提醒比例、P50/P95 时延与每次工具调用数。

先招募 5–10 位目标用户做同样的 3 个任务，与现有“自己找页面 + Copilot”流程比较。建议初始放行目标：至少 8/10 位无需指导完成体检，至少 8/10 位能解释主要风险和下一步；样本小时只作形成性验证，不宣称统计优势。记录弃用原因，再决定阶段 2–4 范围。
