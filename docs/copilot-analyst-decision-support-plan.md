## 1. 产品目标

在现有 Copilot 单一窗口中，支持“解释 → 澄清目标 → 提出候选 → 计算比较 →
给出有条件的优先判断 → 用户确认保存”。不再对所有具体标的一概拒绝，
也不承诺能回答任何问题、稳定收益或存在无条件最优交易。

首个完整任务：用户希望释放风险/资金容量以评估卖 Put，系统明确现金、
融资余额、券商购买力和接盘义务的差别，比较保持不动与受约束候选。
默认以用户确认的风险目标排序，不默认最大化权利金或融资使用。
不得以“模拟”“教育性分析”的标签替代针对具体建议功能的合规评估。

## 3. “分析师知识”不是人物模仿或盲目抓取

### 三类信息必须分开

1. **计算事实**：用户账户、市场数据、确定性工具输出；可支持数值判断。
2. **分析框架**：版本化方法卡，说明适用前提、检查项、反证和失效条件。
3. **外部观点**：具体作者在具体日期的主张；有出处和利益冲突提示，不升级为事实。

首批方法卡：下行/永久损失、估值与经营假设、风险贡献与相关性、融资韧性、
期权接盘与流动性、反方论证与“不行动”。以 Oaktree、Damodaran、AQR 和
OIC/OCC 的公开原始资料为起点；券商实际规则优先于通用教材。
不声称任何作者为产品背书，也不声称复制其私人思维过程。

先用少量人工核验的来源与版本化文件，不先建设大规模爬虫或微调模型。
需要时再扩展检索索引；实时观点用检索，不靠训练权重记忆。

来源字段：source_id、作者、原文链接、发表/抓取时间、来源类型、许可/使用依据、
主题、适用范围、论点、反论点、引用定位、版本、失效状态。
只使用允许获取的公开资料、授权 API 或用户有权提供的材料；不绕过登录/付费墙，
不默认公开可读等于可全文复制/再发布。优先摘要和短引用，保留删除/撤回机制。
博主观点若被纳入，要去重转载、标记赞助/持仓披露与未知利益冲突，不能按粉丝数加权。

外部材料均为不可信数据：检索文本不得修改任务约束、发出工具调用、取得凭证、
覆盖系统规则或写用户记忆；账户内容不得发送给外部检索服务。

## 4. 决策与证据契约

新增可选、向后兼容的 DecisionSupport 结果，不替换现有六段答复和 answer_markdown：

- Task：goal、horizon、scope、missing_inputs、confirmed_constraints、portfolio_revision。
- Snapshot：账户/现金/负债/期权、数据覆盖、逐项时点、方法版本、输入摘要。
- Candidate：candidate_id、操作假设、适用约束、预算、保持不动基线。
- Evaluation：before/after/delta、metric_id、单位、实体、期限、情景、覆盖状态、evidence_refs。
- Judgment：在何目标下优先哪一候选、理由、代价、反证、敏感性、何时失效。
- Coverage：unsupported / insufficient_data / evaluated；缺失不是零。
- Capture：result_version、snapshot_id、是否可保存以及失效原因。

知识论点引用和金融事实引用分栏；不得用作者声望替代计算证明。
“NUMBERS VERIFIED”不能被解释为整段结论正确：界面改为准确描述“数值已核对来源”，
另列计算覆盖、数据时点和 AI 判断，按验证层级展示，不用一个总绿勾遮蔽边界。

### 建议策略

- 能解释通用投资问题；无需账户数据时，不因账户缺失而拒绝概念解释。
- 个性化候选需要明确目标、适用资产、输入覆盖和约束。
- 达标的候选可包含真实持有标的和可计算的假设金额，并明确这是目标约束下的比较判断。
- 先应用硬约束，再做多目标比较；不可比较或互有优劣时显示 Pareto 候选，不虚造总分最优。
- 保持不动始终是合法候选；不可行结果同样是有效答案。
- 低数据质量允许解释和补数据，不允许捏造排序、概率或精确交易金额。
- 隐私、外部注入、资产权限与写操作确认不随建议能力升级而放松。

公开个性化建议上线前须针对服务地区、用户关系和具体功能做专业合规审查；
不是在页尾加一句免责声明就视为解决。此门槛与模型/代码验收分别记录。

## 5. 首个 Sell Put / margin 闭环

原问题：“为了用一点 margin 做 sell put，建议卖哪些股票？”

首先识别/澄清目标：释放现金、减少融资、增加购买力，还是希望通过接盘建仓？
最少缺失输入：目标资金/风险预算、禁止卖出的持仓、券商与账户类型、可接盘标的；
精确合约比较另需到期日/行权价/数量/报价、可用期权权限与担保要求。
能从现有账户确定的字段不重复提问，未知的券商购买力不从杠杆倍数猜算。

默认候选：保持不动；在可售持仓中减轻主要风险贡献；以用户确认的额度增加
流动性/偿融资。对 SGOV 等现金类资产的出售，要同时比较失去缓冲的代价，
不能只因“风险低/容易卖”就把它排第一。不得卖掉为现有短期权提供保护的
股票/腿而不重算覆盖状态。完整期权策略修改未支持前不得生成对应最优排名。

新增卖 Put 计算至少区分：

- 担保现金与券商授信：规则版本、初始/维持担保和可用购买力，未知时显示未知。
- 接盘总金额 K × 实际合约乘数 × 张数，以及当前可用资金/接盘后融资缺口。
- 单独标准 short put 的到期损失边界、净权利金、费用和成本口径；不能代替账户压力损失。
- 到期前重估、标的跳空、IV 上升、买卖价差、提前指派和强平路径。
- 接盘后的集中度、融资、利率变化与担保要求上调压力；并发其他到期义务。
- 已释放资金、收到权利金、担保冻结和融资偿还各记一次，资产负债守恒。
- 场景概率没有可靠估计就不填；Delta 不冒充真实胜率，权利金不冒充净期望收益。

券商担保上调和强平约束无法精确复制时，仅提供条件情景和差异说明，
不把模拟可行解释为券商一定接受订单。

## 6. 单窗口交互

自然语言 → 最少必要澄清 → 可见的工具执行状态 → 保持不动 + 至多两个候选卡。
卡片首屏只回答：建议优先比较什么、为什么、主要代价、缺什么。
用户可选“为什么不是另一个”“压力变大时”“修改金额/约束”“保存此假设”。
展开后显示原始数据、方法引用和完整计算；不新增拟人化分析师窗口或模式选择器。
状态表示实际执行步骤摘要，不展示/虚构模型的私人推理过程。

## 7. 实施顺序与验收

| 阶段 | 交付与依赖 | 必须变红的失败 |
| --- | --- | --- |
| A：回答分级与任务契约 | 通用解释、补数据、用户指定比较、候选建议分开；替换 blanket refusal 的结果级校验；新能力默认关闭 | 正常解释误拒；无数据硬给标的；假设被确认成事实；旧路由/六段契约回归 |
| B：可靠运行底座 | 复用后台设计、原 runs/幂等/CAS；单 worker 有界队列，租约/取消/恢复；作为批量计算前置 | 失联变假完成、重复保存、过期 worker 写入、跨账户结果污染 |
| C：持仓候选比较 MVP | 单快照、硬约束筛选、保持不动+最多两候选；复用比较/融资/期权覆盖服务 | 金额不守恒、卖出覆盖股不报警、漏腿、时点不齐仍说实时、约束违规仍优先 |
| D：方法库与研究整合 | 少量核验方法卡先行；原 Research 数据与反方观点入同一任务，检索可追溯 | 过时观点变事实、外部注入、引用不支持断言、来源失效仍说已核验 |
| E：新增期权假设 | 首发标准美股现金担保 Put；再按券商规则/账户条件开放融资担保和明确覆盖的组合 | 只算权利金、漏接盘资金、乘数错误、跨到期乱求最大损失、把买方/卖方 Greeks 弄反 |
| F：确认与后续复查 | 复用 RiskPlan/签名证据；版本化可比指标后才做跨时间；周期复查另行授权 | 旧结果保存、方法变了却报告风险改善、无授权监控、跨设备读取越权 |

A 可先交付有用解释而不开放未经计算的建议；B 在 C 的多候选生产发布前完成。
D 的少量方法卡设计可与 A 同步，不把知识库当作 C/E 缺失计算的替代品。
不机械规定一功能一 PR；按可独立验收、回滚的切片交付。

后台设计还须补清：用户 JWT 到期后的任务行为、租约回收授权路径、清理职责和最小权限。
不持久化长期 JWT，不把 service-role 或数据库凭证交给模型；过期后需要重新鉴权
而不是为了继续任务绕过 RLS。签名保真与浮点重放容差不是同一个校验。

## 8. 放行标准

1. 截图原问题作为固定 EN/ZH 任务：既不空泛拒绝，也不把 margin sell put 描述为稳定收入。
2. 明确每条工具/数值/结论的来源；账户阈值不被解读为券商保证或安全许可证。
3. 金融公式有独立基准、性质测试和变异测试；同快照、资金守恒、期权符号/乘数必测。
4. 工具合约真实类型、数据库 RLS/并发和真实认证验收；skip 单独报告，不算通过。
5. 外部文本注入、反向指令、误归因、未来数据泄漏和不相干相同数字都有失败样例。
6. 评测同时度量正确拒绝和不必要拒绝；双模型一致不当作真实性证明。
7. 小样本金融人工审阅：建议是否适合目标、考虑哪些反例、风险是否完整、用户是否看懂。
8. P50/P95 时延、队列/预算、取消恢复与移动端单窗口闭环；超时如实报告，不后台无限运行。
9. 新路径 feature flag + 旧行为回退 + 生产合成账户冒烟；不改真实持仓，不自动下单。

## 9. 一手参考资料

- [OIC：Cash-Secured Put](https://www.optionseducation.org/strategies/all-strategies/cash-secured-put) — 担保、接盘与到期边界。

- [Robinhood：Options Collateral](https://robinhood.com/us/en/support/articles/options-collateral/) — 特定券商担保安排，不直接泛化到其他账户。
- [SEC：Robo-Adviser Guidance](https://www.sec.gov/newsroom/press-releases/2017-52) — 自动化个性化建议的监管关注；需针对本产品另行评估。

这些来源用于方法与边界设计，不构成数据再利用许可，也不证明具体候选会盈利。
